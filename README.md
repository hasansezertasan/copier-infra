# copier-infra

A [Copier](https://copier.readthedocs.io) template for a Terraform-managed Cloudflare and
GitHub infrastructure repository, with state in object storage (recommended) or HCP
Terraform. It renders the repository that [infra-copilot](https://github.com/hasansezertasan/infra-copilot)
then sets up and maintains.

## For agents

Your agent is the interface. Copy this prompt into your coding agent:

```text
Install the infra-copilot skills: pick the best installation method for you from
https://github.com/hasansezertasan/infra-copilot/blob/main/docs/installation.md

Then render a new infrastructure repository from
https://github.com/hasansezertasan/copier-infra with copier, in a directory named
infra, and use infra-copilot's setup skill to finish it. Ask me for what you need
(my GitHub owner, the Cloudflare domain and IDs, and the state backend), never ask
for or read credentials, and ask before you create a repository, change settings or
secrets, or push.
```

The prompt points the agent at infra-copilot's
[installation page](https://github.com/hasansezertasan/infra-copilot/blob/main/docs/installation.md),
which lists the install routes for each host. The template asks only for public
identifiers; credentials and the rest of the setup (state bucket, plan and apply
workflows, GitHub Apps, the `production` environment) belong to infra-copilot's setup.

## For humans

### Create a repository

```sh
uvx copier copy gh:hasansezertasan/copier-infra infra
cd infra
git init && git remote add origin https://github.com/<owner>/infra
```

Copier asks for the backend first:

| Backend | State | CI | Extra answers |
|---|---|---|---|
| `object-storage` (default, recommended) | `gcs`, `s3` or `azurerm` bucket | GitHub Actions | state bucket and prefix, plus lock table, region or Azure fields where they apply |
| `hcp` | HCP Terraform workspaces | HCP VCS integration | HCP organization and status check ID; needs a paid tier with team management |

Then ask your agent to use infra-copilot's setup skill in the new repository (hosts that expose
plugin commands, such as Claude Code, also offer `/infra-setup`). Never answer with
credentials; only public identifiers belong in the answers.

### Update a repository

Pull later template changes into a rendered repository with:

```sh
uvx copier update
```

That works only for repositories generated by Copier. A repository created from the former
`infra-template` GitHub template should adopt this template with `copier copy` and reconcile
the result. Switching backend after rendering is a state migration, not an answer change;
follow infra-copilot's runbook.

## Layout

| Path | Role |
|---|---|
| `copier.yml` | questions and Copier settings |
| `template/` | files rendered into a repository; `*.jinja` files are templated, the rest are copied verbatim |
| `scripts/test-template.sh` | renders every backend and runs the rendered project's checks |
| `scripts/test-update.sh` | renders, changes the template, runs `copier update`, and checks answers and local edits survive |
| `.github/workflows/ci.yml` | runs both scripts; `release.yml` versions the template with release-please |
| `docs/` | design notes and MADR decision records behind the template |

## Releases

The template is versioned with [release-please](https://github.com/googleapis/release-please).
Conventional Commits merged to `main` open a release PR; merging it tags the commit `vX.Y.Z`
and creates a GitHub Release. Rendered repositories record the tag in `.copier-answers.yml`,
and `copier update` walks these tags. Until 1.0, breaking changes and features bump the minor
version and fixes bump the patch.

Pin a version when generating a repository:

```sh
uvx copier copy --vcs-ref=v0.1.0 gh:hasansezertasan/copier-infra infra
```

## Development

```sh
pipx install copier==9.18.2   # or: mise use -g copier
mise trust template/mise.toml
mise -C template install terraform   # the Terraform version pinned in template/mise.toml
mise -C template exec -- "$PWD/scripts/test-template.sh"
```
